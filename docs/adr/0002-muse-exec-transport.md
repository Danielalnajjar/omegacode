# Run Muse workers through one-shot exec with private configuration

OmegaCode runs each Muse agent call through `muse exec --json`, using the existing subprocess JSONL helper for framing, stall detection, cancellation escalation, and spawn failures. Each attempt writes a fresh prompt file and starts a fresh process; OmegaCode generates a fresh UUID and passes `--session-id`, with session logging enabled. The SDK and an MSP `muse serve` host are rejected: this single-turn caller needs neither shared sessions nor a second process-lifetime owner.

Each call resolves the source configuration at `$XDG_CONFIG_HOME/muse`, or `~/.config/muse` when unset. When source `settings.json` exists, the call creates a private `<tmp>/xdg/muse` directory (0700), writes the settings (0600) with the top-level `mcpServers` member removed, and symlinks every other source entry. Authentication is never copied, HOME is never overridden, and only the child receives the private XDG_CONFIG_HOME. Read-only always writes private settings, adding top-level `schema_version: 1` and merging `permissions` with `schema_version: 1` and `profiles.omegacode-read-only = {"extends": ":read-only", "approval": "allow_all", "reviewer": "none"}`. Other user profiles are preserved; the OmegaCode profile is authoritative and replaces a same-named user profile. With no source settings, it writes only those schema and permissions fields and still symlinks other entries when the source directory exists. Full-access behavior is unchanged: without source settings there is no override. The private directory and prompt are removed in `finally` only after the subprocess `closed` fence resolves, including SIGTERM-to-SIGKILL escalation on cancellation or stall. Transport rejection remains immediate; only cleanup awaits close, and cleanup failures do not replace the original run error. The Muse 1.2.1-R2847.1 spike measured zero broker clients with this configuration; workspace settings, agents overlays, environment flags, and defaults/policy documents did not provide usable per-run MCP isolation. Permission profiles now coexist with the private settings but do not replace their MCP isolation.

The earlier profile rejection was a CLI clash with `--approval-mode` / `--sandbox-network`, not with private configuration. Read-only passes neither those flags nor `--approval-judge`, `--disable-write`, or `--disable-shell`; approval and reviewer policy come from the derived profile. Full access retains `--approval-mode never --approval-judge off --disable-sandbox --disable-approval`. All headless calls use no foreign personal context, enabled session logs, disabled web tools, and automatic user-input resolution; they never trust the workspace implicitly.

The exec stream emits no usage event. Each attempt passes a fresh `--session-id <randomUUID()>` and leaves session logging enabled in the real Muse data directory (`$XDG_DATA_HOME/muse`, else `~/.local/share/muse`; Muse 1.2.1 ignores a `MUSE_HOME` override, measured). After process completion, sum `payload.event.kind === "model_completed"` records from the session's `session.jsonl` and every `subagent/**/session.jsonl`. Look under today's local and UTC date directories first, then scan date-directory names for the id. Map `input_tokens` and `output_tokens` directly, with `costUsd: 0` for the unpriced subscription. `input_tokens` already includes cached input, as the `AgentUsage` contract requires: a measured second call reported 30,386 input tokens with 27,761 cache reads on a 27,903-token first call. Map `cache_read_tokens` (falling back to `cached_tokens`) to `cacheReadInputTokens`, and `cache_write_tokens` to `cacheCreationInputTokens`; omit cache fields never reported. Like Grok, do not add reasoning tokens to output tokens. Old zero-valued records with null models are valid. Ignore malformed individual lines alongside valid records; a missing, unreadable, or wholly malformed log yields `emptyUsage()` and one content-free phase diagnostic with path and reason. Emit one usage progress event and return the same usage on success. Preserve summed usage on `AgentError` failures after close; `AgentInterrupted` has no usage field and remains unchanged. Structured output is requested in the prompt and parsed and validated locally. Muse 1.3.0 adds `exec --output-schema <FILE>` (meta provider, still a terminal text payload). OmegaCode passes that flag when `versionAtLeast` is 1.3.0 or newer and keeps the 1.2.1 minimum. When the working terminal still fails Ajv, the worker runs one additional `muse exec` whose prompt is the previous answer plus the schema and Ajv errors, at `low` effort and `--max-model-steps 8` — the same extraction shape as pi/Grok, because Muse exec cannot resume a session. That extraction must not re-run the original task: a live `max` retry (`wf_f8b31a6da969`) turned a `Detail`/`detail` miss into a worse enum miss. The runtime's full-task schema retry remains last-resort if extraction still fails. Existing provider defaults, cache identity, and keys remain unchanged. The terminal mapping for auto-resolved `request_user_input` remains unverified because the probe answered normally.
