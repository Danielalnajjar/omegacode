# Run an agent on another machine through an SSH-driven OmegaCode helper

`agent(prompt, { machine })` runs that agent's backend, and its checkout, on another BB machine. A workflow that names machines declares them in `meta.machines`; the run resolves and checks every declared machine before the first agent starts, and an `agent()` naming an undeclared machine is a `WorkflowError` (it aborts the run, like a duplicate key). No `machine` keeps the local path unchanged. An agent that names the run's own machine runs locally but still gets an isolated worktree and branch, as it would on any other machine, so a workflow behaves the same from whichever machine runs it.

**Machines.** A machine is named by its BB host id, its label or short label in Crew's machine table, or its BB name, case-insensitively (`host_dmmpcn4wuu`, `MacBook Pro`, `Pro`). The table is `$OMEGACODE_MACHINE_TABLE`, else `~/Code/skills/shared/plugins/crew/src/machines.json`, else `~/code/...`; the SSH target is the entry's `ssh` field, and an entry without one (pc-box-1 has no SSH) cannot take remote agents. The run's own machine is the `hostId` from `bb status --json`, else the `host-id` file in `~/.bb` or `~/.bb-machines/*`. Validation fails the run before the run-started event, reporting every problem at once, when a name matches nothing; `bb machine list --json` cannot be read, omits the host, or does not report it `connected`; the entry has no `ssh`; or `ssh <target> <omegacode> remote hello` does not answer in-band within 30 seconds with this protocol version, this build, and the same host id, read on that machine from its own BB files. The host-id check catches a stale `ssh` entry that reaches a different machine. The build is a hash of the code each end runs (`dist/` without the viewer when built), because AgentSpec fields change without a protocol bump: an older helper would run a call without a newer restriction such as `codexPermissions`. For the same reason the helper refuses any request field, and any AgentSpec field, it does not know. An `agent()` whose provider is `codex` or `claude-code` fails when the table lists providers for that machine and omits it (the Air lists only `codex`). The remote command is `omegacode`, or `$OMEGACODE_REMOTE_COMMAND`, run through the remote login shell.

**Transport.** The brief recommended driving each backend over SSH stdio. Every backend except Codex does local preparation before it spawns anything: Claude profile resolution, Grok and Muse private settings, binary and version preflight. Re-creating that over raw stdio would fork each worker into a local and a remote copy. Instead, the remote side runs a hidden subcommand, `omegacode remote <hello|have|prepare|run|collect|cleanup>`, which uses the normal `DefaultWorkerFactory` on that machine with its own logins, config and binaries. Locally, a `RemoteWorker` implements the `Worker` interface: it sends the `AgentSpec` as one JSON line, relays each `WorkerProgress` line to `ctx.onProgress`, and returns the `done` line's `AgentResult` or rebuilds the `error` line's `AgentError` with its code, retryable flag and usage, so `withRetry` behaves as it does locally. Journal, resume keys, schema validation and the corrective retry, events, budget, timeouts and retries stay in `primitives.ts` on the run's machine. Each attempt is one `ssh -T -o BatchMode=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=4` process. Exit codes are never trusted (Tailscale SSH to the Air always exits 0): a call succeeds only on its in-band terminal line, and a stream that ends without one is `remote_connection_lost`, a non-retryable agent failure that names the machine and the last stderr lines. `--fake` reaches the helper, which then uses the FakeWorker; the checkout is still real. The run sends what is left of the agent's time limit with each `run`, and the machine stops the turn when it runs out, so a turn whose link is gone without an EOF (the run's machine went to sleep) does not run on. A pinned `claudeProfile` is resolved on the machine (the profile id must exist there) at each attempt rather than once per agent: the resolution is a lookup of a stable id, so repeating it changes nothing, while holding one prepared environment across attempts would need a long-lived session protocol.

**Stopping.** `remote run` is a supervisor: it starts the worker in a child process that leads its own process group, and writes its terminal line only after that whole group has exited. Abort, an `abort` line, stdin EOF (the run or the link went away) or a signal forwards the abort, waits 5 seconds, then kills the group. `collect` and `cleanup` first stop any supervisor and group recorded for the worktree and fail, keeping the worktree, if they cannot. So a later attempt or a collection never runs beside a writer that is still going. Locally, an abort writes the `abort` line and closes stdin; `run` gets 15 seconds to report before `ssh` is killed, every other call is killed at once.

**Checkout.** A remote agent always gets an isolated checkout, as `worktree: true` does locally; `worktree` may still name its branch. The base is the run repository's `HEAD` when the agent starts, so it may exist only on the run's machine. GitHub is never involved and no credential is needed. Each machine keeps one bare cache per source repository, `~/.omegacode/remote/repos/<name>-<root commit>-<source id>.git`, where the source id hashes the run machine's hostname and the repository's common Git directory. Before every remote agent starts, `have` lists the cache's ref tips; the run bundles the base and all its local branches minus every tip it also has, and `prepare` streams the bundle in behind its byte length and SHA-256, sets the cache's branches to match, and adds a worktree for this attempt on an internal branch, `omegacode/<runId>-<index>-<nonce>`. Refreshing the branches per agent is what lets a later agent on any machine diff or merge an earlier agent's branch by name, as `builtins/bake-off.workflow.js` does locally. The branch snapshot carries a strictly increasing stamp, and the machine applies it only when it is newer than the last one applied, so a delayed older `prepare` cannot rewind or delete a branch a running agent reads; branches checked out by a live remote worktree are never changed. `run` and `prepare` keep stdin open until the run has their reply, so a run that gives up closes it: `prepare` then adds no worktree, or removes the one it just added. When a `prepare` fails on the run's side, the run also removes the attempt by name, which the attempt's lock orders after a `prepare` still finishing there. Each attempt gets a new nonce, so a worktree kept after a failed collection is never reused by a resume.

Locks are per machine and name their holder's process id, so a lock left by a helper that died is taken over at once. A per-repository lock covers only the cache's objects and refs: the bundle fetch and the branch update, whose deletes run in their own transaction before the updates so a branch renamed between `feat` and `feat/x` still mirrors. The checkout itself is added outside it, so a fan-out of many agents to one machine checks out in parallel; the run checks the machine's tips against its repository in one `git cat-file --batch-check`, outside its own worktree lock. A per-attempt lock orders that attempt's `prepare`, `collect` and `cleanup`, so a salvage collection waits for an earlier collection still running on the machine instead of colliding with it in the same index. Each attempt has a lease that `prepare`, the running agent (each minute) and `collect` renew. The next `prepare` for that repository on the machine removes worktrees whose lease is more than 24 hours old and whose agent is not running: a run that died, or a worktree kept after a failed collection, is cleaned up a day later.

When the agent finishes, after its retries and any corrective schema retry, `collect` stops the attempt's processes, commits anything uncommitted as `omegacode: uncommitted changes left by agent <index>` (no hooks, no signing), and, when `HEAD` is ahead of the base, streams back a bundle of `HEAD` minus the base. The run verifies the length, hash and bundle, fetches it into `refs/omegacode/incoming/<name>`, and publishes the local branch (`aw/<runId>-<index>` or the named one) with a compare-and-swap against the tip recorded at `prepare`, refusing a branch checked out in a local worktree. A branch that moved meanwhile fails the collection and leaves the incoming ref and the remote worktree in place. Two in-flight agents of one run may not name the same branch. Collection is awaited, not raced against the deadline: the deadline aborts its transfer, the publish checks the abort signal immediately before the ref update, and a publish that has begun settles before any failure is journaled or a salvage collection starts. A remote agent's success is journaled only after its commits are published, with the branch and its head, so a dropped connection during collection is an agent failure, never a success whose work is missing. A failed or interrupted agent is still collected, within 2 minutes, as a failed local worktree is preserved. Zero commits ahead means no local branch, as a clean local teardown deletes its branch. `cleanup`, bounded to 2 minutes, then removes the remote worktree and its internal branch. Sandbox follows the local rule: an explicit `worktree` forces `workspace-write`; an implied one keeps the resolved sandbox, so a read-only reviewer stays read-only.

**Journal key.** `machine` is not part of the resume key: placement is capacity, not meaning, and the commits of a completed remote agent are already in the local repository. Moving an agent to another machine on resume replays it. The implied worktree does change the key, because the call's result changes from in-place edits to a branch. The `started` entry and the agent events carry `machine`.

**Not supported.** Machines without an `ssh` entry; a `cwd` outside a Git repository; uncommitted or untracked local files (a remote checkout starts from `HEAD`, like a local worktree), tags and remote-tracking refs; files Git ignores, in either direction (an agent's ignored output, such as build products or `.context/`, stays on the machine and is deleted with its checkout; only commits and the snapshot of tracked and untracked, not ignored, files return); submodules and Git LFS content; reattaching to a remote turn after the run's process dies (the agent re-runs on resume, as locally); and different protocol versions on the two ends. A machine's providers are whatever that machine has logged in, as seen from a non-interactive SSH session; nothing is copied between machines. Measured on 2026-10-31: Codex worked on WSL and the Pro. Claude Code did not: the Pro keeps its OAuth login in the login Keychain, which an SSH session cannot read ("OAuth session expired and could not be refreshed"), and WSL's default Claude home is not logged in. A pinned `claudeProfile` resolves through `bb subscription resolve-omega`, which needs that machine's `bb` to reach the BB server, and outside a BB thread on WSL it cannot.
